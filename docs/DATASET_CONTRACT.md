# 数据接入约定：原始数据尽可能不受限

状态：统一评测入口的数据规范；[静态点查询第一版](UNIFIED_BENCHMARK.md) 已接入单文件 reader 和规范键视图，目录分片、清单和外部 reader 插件仍待实现。旧 TLI runner 保留独立流程。这里规定 benchmark 如何接收数据，不要求用户先制作一种“benchmark 专用数据集”。实现侧见 [INDEX_CONTRACT.md](INDEX_CONTRACT.md)。

## 1. 用户交付的是位置

用户指定数据集位置和实现位置，运行一次评测脚本，得到详细结果。数据集可以来自任意领域，可以是原始文件、目录中的分片或数据清单；不要求来自本项目的下载器，也不要求附带本项目元数据。

**不对原始数据规定文件名、目录、容器格式、编码、行数、排序、唯一性、键长或总字节数上限。** 不要求用户先过滤空键、NUL、高位字节或长键，不要求准备 SHA-256、排序文件、统计信息和来源 manifest。

数据集无关指评测流程不依赖特定数据集的名称和来源。不同数据的性质会影响性能，详细报告必须保留这些差异。

```text
用户提供数据位置 → reader/取键规则 → benchmark 的内部键视图
                                             ↓
用户提供实现位置 → 实现适配器 ← 负载、校验、计时 → 详细报告
```

本项目当前评测字符串索引，因此仍需要确定“原始数据里的什么是键”。这是读取/取键的问题，不是限制数据来源。不能承诺自动理解任何未知格式，更不能把整行 JSON、数值的十进制表示或任意字段默认为用户期望的键。

## 2. reader 负责读取，不要求用户改变原始数据

读取分两层：

1. 核心之外的 reader 理解文件格式、分片和字段选择，逐条输出有长度的键字节；它可以是内置 reader，也可以是外部 reader。
2. 核心只消费键，不认识 URL、词表、JSON、数据库导出或其他来源格式。增加数据来源只增加 reader，不修改索引接口和评测逻辑。

能明确识别的格式使用内置 reader；格式或取键存在歧义时要求指定 `--reader` / `--key`，并在构建实现前报出缺少的信息。未知格式允许接入 reader，不以“不属于预置数据集”拒绝。内置 reader 的实际支持清单由 `scripts/benchmark.py --help` 给出，不能把设计支持写成已实现支持。

reader 的逻辑协议如下；这是扩展接口的语义要求，具体 Python 函数签名以当前实现为准：

```python
iter_keys(dataset_location, reader_options) -> Iterator[bytes]
```

`dataset_location` 是用户指定的位置，`reader_options` 包含取键、编码、分片顺序等可复现设置；每次产生一个完整键的字节。文本编码只在 reader 中处理，二进制输入可保留原始字节。输入可以流式读取，不要求事先知道键数或全量载入内存。

reader 必须完整读取被选中的输入，或明确报告失败；不能静默截断长键、读到固定字节数就结束、跳过坏记录或自动抽样。用户显式选择的过滤/抽样可以执行，但规则和丢弃计数必须写入报告。不修改源数据。

## 3. 内部语义固定，原始数据不用满足内部格式

为了让不同实现接受同一个实验，benchmark 在读取后构造内部视图：

| 项目 | 评测核心的行为 |
| --- | --- |
| 键 | 任意有限字节串；允许空键、NUL、高位字节和前缀键，没有人为的统一键长上限 |
| 相等 | 长度与所有字节相同；不暗中大小写折叠、重编码或规范化 URL |
| 有序操作 | 按 unsigned byte 字典序比较；相同前缀时短键在前，不使用 locale |
| 原始乱序 | 核心构造规范排序视图；用户不必预排序 |
| 原始重复 | 当前唯一键 map 实验中合并相同键，报告原始条数、唯一键数和重复数；不把重复次数当成访问热度 |
| 空数据 | 可用于正确性边界检查；无法生成的性能负载单独 skipped，不称数据集非法 |
| 值 | benchmark 生成 `uint64_t` 载荷，默认采用键在完整排序唯一集合中的从 0 开始序号模 `2^64`；不读取业务 payload |

规范排序/去重是 benchmark 的公开准备步骤，不是用户交付条件。原始输入保留，报告明确本轮采用 `unique-key-map` 语义；真正的多值键实验需要另设接口，不能声称已覆盖。值在划分初始集合、插入和删除时不重新编号；更新负载可以改变它。它是载荷，不是实现可以自行推断的当前位置。

物理机器和特定 reader/实现仍有实际资源边界。超出资源时报告哪个阶段、什么原因没有完成，不能把某机器的内存预算写成全局数据集限制。正式运行使用显式资源预算；预算不足时允许用户调整、选择可扩展的 reader/准备方式，或明确采样后重新运行，不能悄悄改小数据。

## 4. 数据和负载是两个输入维度

数据决定候选键集合；读写比例、初始加载比例、命中率、热点、Zipf、查询与插入顺序属于工作负载配置。原始数据也可配独立访问日志 reader；不能从重复记录擅自推断真实访问分布。

同组比较必须复用相同初始键值和操作序列。初始键值按统一字节序排序后交给实现，后续插入按操作序列执行。命中与否相对于操作发生之前的逻辑状态判定；尚未插入的候选键可以构成当时的未命中。

实现的适用性检查覆盖初始键、全部操作涉及的键/边界及新值。某个实现不支持长键或 NUL 时，报告该实现与本轮数据/负载不兼容，不拒绝该数据集，也不为该实现静默过滤键。完整操作语义见 [INDEX_CONTRACT.md](INDEX_CONTRACT.md)。

## 5. 描述信息由 benchmark 生成

用户已有的来源、许可、快照和生成配方可以一并读取；没有时标为未提供，不阻止本地评测。评测程序自己记录：

- reader 及版本、取键/编码/排序/去重规则，显式过滤和抽样设置。
- 输入身份、内容哈希、实际读取规模；键集合的逻辑哈希。
- 原始/唯一/重复/过滤条数、总键字节数、空键/NUL/高位字节/前缀键情况。
- 键长、相邻最长公共前缀的统计及计算方法。
- 本轮工作负载、操作序列身份、seed、初始集合、生成器版本。

逻辑哈希对规范排序唯一键集合计算 SHA-256。规范流为 ASCII `string-dataset/v1`、一个 `0x00` 字节、键数，然后依次为每个键的长度和原始键字节。键数和长度均使用最短形式的 unsigned LEB128 编码，不设置固定字宽的长度上限。物理文件哈希与逻辑哈希分开记录；更换容器但保持键集合相同，不改变逻辑哈希。

耗时、规模过大或不适用的附加统计可以标为 unavailable 并注明原因，不能为了完成统计静默改变实验输入。核心键语义和实现能力预检所需的性质必须完成检查后才能测量。

## 6. 当前工具的限制只是迁移事项

现有 TLI 格式为小端 `uint64` 键数，逐键小端 `uint32` 长度加键字节。当前脚本的 4096 字节、NUL、最少键数、文件名和路径限制，是旧工具的限制，**不是本项目未来统一入口的数据接入规定**。已有数据不需要换来源；应由 reader 接入并移除核心对这些约定的依赖。

当前来源说明 [DATASETS.md](DATASETS.md) 继续记录那些具体样本的处理方式；本约定不把它们的过滤策略套用到用户其他数据。原始数据格式损坏、无法确定取键或读取失败必须明确报错；“数据不是预先清洗过的 benchmark 文件”不是拒绝理由。
