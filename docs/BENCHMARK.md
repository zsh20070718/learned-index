# Benchmark 范围与实验语义

## 产品目标与两侧边界

项目提供数据集与索引实现之间的评测层：**用户指定数据集在哪、实现在哪，运行统一脚本，得到详细评测结果。** 数据来源和实现源码均可在本仓库外。键长、文件大小、原始排序或重复记录不作为统一入口的数据接收限制。

两侧规范分别为 [数据接入约定](DATASET_CONTRACT.md) 和 [实现接口契约](INDEX_CONTRACT.md)。数据通过 reader 提取键，实现通过薄适配器提供统一操作；核心负责准备数据、构造负载、能力匹配、独立校验、测量和报告。

目标命令形式如下，**是待实现的入口约定，当前仓库尚无 `scripts/benchmark.py`**：

```bash
python3 scripts/benchmark.py \
  --dataset /path/to/dataset \
  --implementation /path/to/index-adapter \
  --output results/my-evaluation
```

`--dataset` 接受文件、分片目录或数据清单；`--implementation` 的适配包发现规则见实现契约。格式明确时自动选择内置 reader；有歧义或属于外部格式时通过 `--reader` 和 `--key` 明确读取/取键。用户不必预先制作 TLI 二进制文件、排序去重或编写数据 manifest。未指定 output 时生成新的独立结果目录；已有结果不覆盖。

只给两个位置即可采用脚本版本绑定、在报告中完整展开的默认 workload 配置运行；也应允许 `--workload` 指定配置文件、重复 `--implementation` 做横向比较。默认负载不得自动采样/截断用户数据，操作数量等实验参数必须显式记录。具体默认负载参数随入口实现确定，不把今天 smoke 的规模当成通用限制。

一次运行应自动完成读取、准备、负载生成、实现构建、能力检查、正确性校验、重复测量与汇总；实现构建前先验证用户输入和适配描述。必须输出所有请求组合的状态，不能悄悄丢掉失败或不支持项。

详细报告至少包含：

| 输出 | 必须说明什么 |
| --- | --- |
| `report.md` | 人可读总览：运行规模、哪些组合通过/失败/不支持、性能及可比较范围 |
| `report.json` | 完整配置、来源/哈希、读取与数据准备规则、数据性质、实现/适配器版本和能力、环境、逐组合状态及原因 |
| `summary.csv` | 逐实现/负载的构建耗时、吞吐量、独立无校验测量的延迟分位数、内存分项及重复轮次汇总；未知项标明不可用 |
| `samples.csv` | 原始逐轮样本，能复算汇总、查看离散程度；失败记录没有虚构性能数值 |
| 诊断记录 | 定位读取、构建、校验或执行失败；报告可定位的操作序号与错误类型，避免默认倾倒原始键内容 |

不把不同操作语义、适配方式或内存口径混为同一种指标。无法运行时仍产出失败阶段与原因。当前任务先确定这两侧契约和入口目标；以下内容描述现有 TLI 开发入口，不能视为上述流程已经实现。

## 当前 setup 的边界

本项目建设字符串索引 benchmark，工作重点是已有索引适配、工作负载、正确性校验、公平测量和结果复现；不开发新的索引算法。当前仅完成开发入口及部分基线接入。默认构建直接引用固定版本 TLI 的 `benchmark.h`、`generate.cc`、`competitors/art.h`；`StdMap` 实现相同接口。上游工作区保持原样，便于对照和后续选择性接入。GRE 默认 `microbench.cpp` 实例化整数键，目前仅下载参考源码，未构建其完整依赖和子模块。

TLI 原始完整构建涉及 MKL、TBB、jemalloc 及大量整数索引实例化。当前入口只需 Boost 头文件和标准线程库；SIndex、ARTOLC、Wormhole 等没有被伪装成已运行的比较项。

## 工作负载

键按字节字典序排列，每个唯一键的 value 为其在完整排序数据中的位置。点查找返回该位置；区间查询返回闭区间 `[lo, hi]` 内 value 的总和；插入保留相同 value。当前接口和生成器不支持 update/delete。

Smoke 的 6 个基本负载对应课程字符串部分给出的读写比例，另加 TLI 两种插入模式。混合负载中，区间操作占“读操作”的 5%，传给 TLI 时需要换算为全部操作的比例：

| 名称 | 点查找 | 区间查询 | 插入 | 插入模式 |
| --- | ---: | ---: | ---: | --- |
| lookup | 100% | 0% | 0% | — |
| scan | 0% | 100% | 0% | — |
| read50_insert50 | 47.5% | 2.5% | 50% | equality |
| read80_insert20 | 76% | 4% | 20% | equality |
| read20_insert80 | 19% | 1% | 80% | equality |
| insert | 0% | 0% | 100% | equality |
| delta_insert | 47.5% | 2.5% | 50% | delta |
| hotspot_insert | 47.5% | 2.5% | 50% | hotspot，范围比例 0.5 |

区间端点由上游生成器选择，目标约 100 个元素，并非严格固定返回 100 条的 scan API。初始键数为完整数据量减去本负载插入数，因此这些 smoke 组合的初始加载比例并不相同。每种索引在相同组合中复用同一份 workload。

两类合成键为随机变长 ASCII 字符串、带分组共享前缀的类 URL 字符串；都添加唯一后缀并固定 seed=42。它们控制键形态，不控制查询访问分布。TLI 的 hotspot 参数控制插入键所在区间，不是热点查询分布。

另由本地 `make_lookup_workload.py` 生成七种静态点查询负载。它们复用同一份数据，不包含插入或区间操作：

| 名称 | 查询访问分布 | 请求未命中比例 |
| --- | --- | ---: |
| lookup_uniform | uniform | 0% |
| lookup_miss50 | uniform | 50% |
| lookup_miss100 | uniform | 100% |
| lookup_hotspot | hotspot：90% 概率访问前 10% 源键 | 0% |
| lookup_hotspot_miss50 | 相同热点设置 | 50% |
| lookup_zipf | Zipf，指数 1.1，按字节排序名次 | 0% |
| lookup_zipf_miss50 | 相同 Zipf 设置 | 50% |

uniform 在完整源键数组中等概率有放回抽样；hotspot 将字节排序后的前 `max(1, floor(N × hotset_fraction))` 个键作为热区（最多 N−1），按照 `hot_probability` 选择热区/冷区，再在选中区域均匀抽样。它与 TLI 的热点插入模式是两个不同维度。Zipf 在有限的 N 个源键上归一化权重 `r^-exponent`，r 为从 1 开始的字节排序名次；指数默认 1.1，支持 0–3，0 复用均匀抽样路径。使用浮点累计概率表及二分抽样，时间 O(N + operations × log N)，额外空间 O(N)。这是合成访问分布，不能当成真实流量的热度排名。

未命中次数固定为 `floor(operations × miss_ratio)`，随机分配到操作位置。命令行比例按十进制保留，并以整数分数计算未命中数及热区大小，避免 `100 × 0.29` 因浮点误差少算一个。元数据的 `*_decimal` 字段保留精确请求值，数值字段供常规统计读取。缺失键由源键追加随机后缀产生（超过 4096 字节时截短源前缀），检查其不属于完整数据集，并按源键缓存。这样的缺失键通常与已有键共享前缀，键长可能增加，不代表所有真实未命中分布；性能差异不能完全归因于命中率。

源键抽样、未命中位置及缺失键生成使用独立的固定种子随机流；修改命中率不会改变源键访问序列。各 `.json` 和 manifest 的 `lookup_workloads` 保存实际比例、冷热源键计数、唯一查询键数量及校验和。热点访问比例是概率采样结果，不保证每次恰好 90%。

## 指标与校验

- 上游原始吞吐量 CSV 无表头：`index, build_us, reported_index_bytes, throughput_mops_per_s`（重复测试会增加构建时间和吞吐量列）。吞吐量数值单位是百万操作/秒。
- 上游延迟模式输出 `index, build_us, reported_index_bytes, avg_ns, p50_ns, p99_ns, p999_ns, max_ns, stddev_ns`，仅单次运行。Smoke 的 verify 日志包含该输出，但校验有额外开销，不作为正式延迟测量结果。
- ART 的 `size()` 统计树节点及部分叶子键值存储；StdMap 统计分配器所分配的 map 节点。这些都不是进程 RSS，口径不统一，不可直接用于跨实现内存排名。
- 入口将上游 `run_failed` 转为非零退出码；Smoke 同时检查返回码和 `RESULT`，防止“索引不适用、被跳过”被当成通过。
- `--through` 在上游关闭逐操作校验。Smoke 先单独 `--verify` 再测吞吐量，且每次重建索引。本地 CheckedIndex 使用独立 map 参照检查查询、每次插入后立即读回，最终逐键检查全部预期键值，补足纯插入的上游校验缺口；不支持的 update/delete 仍不参与校验。
- 上游无校验路径未消费查询返回值，内联适配器可能被编译器消除实际查询。本地 ObservedIndex 为所有索引的查询结果增加编译器屏障，保留实际计算；GCC/Clang 下不增加硬件 fence。旧版本的吞吐量结果不能与此版本直接比较。
- `scripts/smoke.py --repeats N` 支持 1–10 轮，记录每轮构建时间与吞吐量，汇总取中位数。数据与负载哈希、键数、操作数、seed 和重复数写入 manifest；不把一轮成功当作稳定的性能结论。
- 默认 smoke 仅用于开发环境验收，规模小、未绑核、未隔离系统负载，不能作为论文实验数据。

## 校验器测试与比较项边界

`benchmark_contract_checks` 使用故障注入确认校验器能发现错误命中、错误区间和、丢失插入和旧键损坏，同时检查合法操作可以通过。测试对象是 benchmark 的校验机制。

上游 ART 的 RangeQuery 在空区间可能错误计入首个后继键；当前生成器使用非空区间，不能据 smoke 通过推断所有边界正确。后续接入更广的负载时应报告该限制，并以可追溯补丁或能力限制处理，避免静默改变被测算法。

## 后续 benchmark 工作

1. 按已确定的 [实现接口契约](INDEX_CONTRACT.md) 接线统一入口：外部 reader 和实现适配包发现、bulk load/find/insert/update/erase/scan 的完整语义、能力匹配及详细报告。签名见 `src/index_contract.h`；目前尚未替换旧 TLI 接口。
2. 接入已有字符串学习型索引实现（如 SIndex、LITS）及更多传统字符串基线（如 ARTOLC、HOT、Wormhole）。逐一核对原始论文代码、许可、key 限制及所需依赖；不把整数索引直接包装为字符串算法。
3. 已支持静态点查询的未命中、uniform/热点/Zipf 访问分布；继续扩展混合写入时的未命中、数据偏移、键长度/共享前缀控制和更新删除负载。TLI 字符串生成分支仍将 negative lookup 比例固定为 0，本地新生成器单独补足静态点查询。
4. 已接入英文词表、MemeTracker URL 和短语，并保留合成对照，详见 [数据集说明](DATASETS.md)。继续拓展 DBLP、IMDb、Reddit、Wiki 等独立来源，记录许可、版本、校验和、排序/去重/编码规则。真实数据不放进 Git。
5. 扩展被测索引的未命中、空区间、前缀关系和边界键测试；对不满足统一契约的实现显式报告限制。增加 update/delete 后扩展最终状态校验；并发实验需另外验证并发语义。
6. 正式测量分离构建耗时、吞吐量、无校验延迟分位数和统一内存指标；记录 CPU、编译器/参数、数据哈希、随机种子、提交号和重复轮次。再逐步加入 perf、线程扩展和长时间实验。

## 添加一个初始适配器

新统一入口的适配器按 [INDEX_CONTRACT.md](INDEX_CONTRACT.md) 和 `src/index_contract.h` 开发，不把 TLI 的文件名或接口约定继续向外传播。仅为维护当前旧入口时，才参考 `src/std_map.h`，在 `src/string_benchmark.cpp` 注册 `RunIndex<YourIndex>(bench, verify)`；这条旧路径固定单线程，只提供 lookup、inclusive range sum、insert，不能称为 v1 接入完成。
