# 本周改进记录 · 2026-10-17

本周把统一 benchmark 从单线程静态查询推进到**共享索引实例的多线程只读评测**，并实际接通两位同学的现有模型适配包。项目继续负责数据、负载、正确性、公平测量和复现，索引算法由同学或外部实现提供。

## 为什么做这次更新

重新核对原始课题材料后，确认多种 workload、访问分布与并发支持都属于整体研究方向。前一周统一入口已具备均匀、热点、Zipf 查询，却不能回答“同一索引增加查询线程后会怎样”。同学各自的模型实验也需要相同的接入和校验条件。

这周完成两条互相配合的工作：为已经支持并发读取的实现提供线程扩展实验；核对并运行同学已有接口，让尚未声明并发能力的模型继续参加单线程比较，清楚报告其边界。

## 具体更新

每个适配器只编译一次，各线程数使用同一个可执行程序和查询文件。默认仍只测单线程；未声明并发安全的实现不进入并发查询。延迟始终是另建实例的单线程抽样，报告明确标出它不是并发负载下的尾延迟。

新结果采用显式 v2 schema；原有 v1/v2 负载、查询文件格式和默认查询序列保持兼容。报告解析器严格核对线程数、工作量划分与并发校验计数；审查还修复了非法状态字段可能中断整批实验的故障隔离问题。

## 怎么使用

在仓库根目录运行，输出目录必须尚不存在：

```bash
python3 -B scripts/benchmark.py \
  --dataset examples/keys.txt \
  --implementation adapters/std_map \
  --implementation adapters/sorted_vector \
  --workload examples/workloads/parallel-read.json \
  --threads 1 2 4 \
  --output results/parallel-read
```

打开 `report.md` 看结果，再用 `scaling.csv` 对照线程扩展，或用 `workers.csv` 检查各线程是否承担相同口径的工作。`--threads` 控制查询线程，`--jobs` 控制编译任务，含义不同。详细口径见 [并行评测说明](PARALLEL_BENCHMARK.md)。

## 实际验证

- Python 回归 **55 项通过**，包括历史查询指纹、分布、严格 v2 解析、缺失/失败基线、矩阵故障隔离和源码身份记录。
- 完整 CTest **6 组通过**，包含 C++ 并发故障注入、旧 TLI 的 **60 个 smoke 案例**及既有数据/负载检查。
- 两个基线的实际 CLI 在 1/2/4 线程下 **6 个组合通过**；两个同学模型的实际 CLI 则为 **2 个单线程通过、4 个并行不支持**。
- 三类真实键数据各 10,000 个唯一键，分别测 uniform/hotspot/Zipf，每轮 200,000 查询、10% 未命中、5 轮重复。两个基线 × 三线程数共 **54 个组合全部通过**，保留 **270 轮吞吐量、270,000 个单线程延迟样本、630 条工作线程样本**。
- 同样九份真实数据负载用于两个同学模型：**18 个单线程组合通过，36 个并行组合明确不支持**；保留另外 **90 轮吞吐量、90,000 个单线程延迟样本**。不把这些不支持项写成成功或零吞吐量。
- 独立读取二进制输入，复核实际键值/成员关系、查询哈希、线程分工、吞吐量公式、加速比及报告行数。已有结果拒绝覆盖；原始数据和外部源码 checkout 保持不变。
- 代码审查通过；源码身份增量另经针对性审查。实际 Git 读取不改 checkout 的索引或配置，不可用/超时不会伪装成干净状态。

真实数据键的来源和抽样方式沿用 [数据集说明](DATASETS.md)；访问序列仍是可控的合成负载。多场景实验复用实际 CLI 编译并核对哈希的同一批可执行程序，避免重复编译；每轮索引仍独立重建。公开的 [基线结果 CSV](experiments/parallel-read-2026-10-17.csv) 保留全部 54 行指标、离散程度及数据/查询/程序哈希；[同学接入结果 CSV](experiments/peer-integration-2026-10-17.csv) 保留全部 54 行状态和固定提交。

### 小规模实验观察

以下列出全部九种场景中，4 线程相对本实现 1 线程的吞吐量中位数比值：

| 键数据 | 访问分布 | std-map 加速比 | sorted-vector 加速比 |
| --- | --- | ---: | ---: |
| 英文词条 | uniform | 1.48× | 1.42× |
| 英文词条 | hotspot | 2.43× | 1.18× |
| 英文词条 | zipf | 1.10× | 1.09× |
| MemeTracker URL | uniform | 2.62× | 2.53× |
| MemeTracker URL | hotspot | 2.17× | 2.30× |
| MemeTracker URL | zipf | 1.91× | 2.11× |
| 自然语言短语 | uniform | 2.23× | 2.26× |
| 自然语言短语 | hotspot | 1.79× | 1.40× |
| 自然语言短语 | zipf | 1.55× | 1.63× |

这组结果说明线程扩展不是固定的四倍，数据形态、访问集中程度和调度都会影响观测。它没有绑核、没有专门预热，键数仍较小，不能推导算法排名；单线程与多线程运行都有原始样本可复查，波动见 CSV。
