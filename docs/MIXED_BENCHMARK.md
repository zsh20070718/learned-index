# 动态混合负载、扫描与模型参数

统一入口现在还可评测一个索引在连续查询与修改后的行为。评测层生成固定的操作序列，由独立参照检查每一步结果，再从相同初始状态重复测量。索引实现和模型仍由外部适配包提供。

## 运行一个混合场景

```bash
python3 -B scripts/benchmark.py \
  --dataset examples/keys.txt \
  --implementation adapters/std_map \
  --implementation adapters/sorted_vector \
  --workload examples/workloads/mixed-all.json \
  --output results/mixed-all
```

输出目录必须尚不存在。std-map 提供基本的增删改查和拥有结果的前向扫描；sorted-vector 保留静态定位，可以参加纯扫描场景，遇到写入组合明确报告不支持。多个实现使用完全相同的初始行和操作文件，不会为某个实现删除它不支持的操作。

这轮动态负载按单线程执行。`--threads` 大于 1 的混合组合会报告 `unsupported`；原有静态点查询的多线程只读流程继续可用。模型支持单线程修改，不代表它支持并发写入。

## 五份场景

| 配置 | find | insert | update | erase | scan | 初始加载 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `mixed-read-insert.json` | 80% | 20% | 0 | 0 | 0 | 50% |
| `mixed-update-delete.json` | 50% | 15% | 20% | 15% | 0 | 50% |
| `mixed-scan.json` | 50% | 20% | 0 | 0 | 30% | 50% |
| `mixed-all.json` | 40% | 20% | 15% | 15% | 10% | 50% |
| `scan-only.json` | 0 | 0 | 0 | 0 | 100% | 100% |

前四份每轮 20,000 次操作，纯扫描为 10,000 次，均重复 3 轮、固定种子 42。扫描长度为最多 16 条。这是操作类型的配比；例如一次删除可能返回 `not_found`，报告会另列实际结果，而不是把所有删除尝试都算作成功删除。

操作数按精确十进制权重分配：先向下取整，剩余名额按余数从大到小分配，同余数时依次为 find、insert、update、erase、scan，然后用固定随机流打乱顺序。小负载也不会悄悄改变总操作数。

## 自定义配置

```json
{
  "schema": "mixed-operations/v1",
  "seed": 42,
  "operations": 20000,
  "initial_load_fraction": "0.5",
  "operation_weights": {
    "find": "0.8",
    "insert": "0.2"
  },
  "read_miss_ratio": "0.1",
  "scan_length": 16,
  "repeats": 3,
  "latency_samples": 0
}
```

权重省略项为零，总和必须精确为 1；不提供整个权重对象时默认查询 80%、插入 20%。未知字段、重复字段、非法比例和无效参数会在构建适配器之前报错。动态版本暂只定义均匀选键，不接受静态热点或 Zipf 字段，避免把不同含义的偏斜混为一谈。

`initial_load_fraction` 明确控制本次实验初始加载多少键；数据仍完整读取和去重。程序按种子选取初始键，并按字节排序，其余源键留作后续插入。优先插入这些真实保留键；不足时使用经过冲突检查的确定性后缀键，报告会区分真实源键与合成插入。初始 value 保持该键在完整规范集合中的序号，不按子集重编号。写入操作使用显式、确定性的 uint64 新值配方，覆盖 0 和 UINT64_MAX，元数据记录该策略。初始化、选键、值与操作顺序使用可复现的随机流，负载准备不进入索引计时。

`read_miss_ratio` 是 find 的未命中目标，动态空状态可能使实际未命中增加；以报告中的实际命中数为准。序列还覆盖重复插入、缺失更新/删除与值变更等分支。`scan_length=0` 合法，返回空结果；扫描到末尾允许少于请求条数。

本轮动态负载不测延迟抽样，`latency_samples` 必须为 0。它不会把另建空状态实例的查询延迟冒充动态混合负载下的延迟。

## 模型参数通过同一入口传入

对外部适配包可重复指定：

```text
--parameter block-residual-delta:region_size=512
--parameter ours-context16:ov_threshold=64
```

冒号前是本次 manifest 的实现 ID，等号前是参数名，后面保留字符串值。参数按名称排序后传给每个新实例的工厂；配置与各运行结果均记录有效参数。静态点查询、多线程只读和动态混合都使用同一条传递链。

不存在的实现 ID、格式错误或重复的“实现/参数名”组合会在构建前拒绝。参数是否受支持、取值是否合法，由原适配器验证；原始异常中的键或任意文本不会直接写入诊断。两个内置基线没有可调模型参数，传入未知参数应明确失败，不能静默忽略。

## 校验与计时口径

每个配置先核对能力、键值域、空构建和边界，再用独立的 unsigned-byte 有序 map 按序模拟：

- find 必须精确区分缺失与合法值 0。
- insert 遇到已有键必须保留旧值，update 遇到缺失键不能插入。
- erase 后必须读不到该键；每次修改后都另行读回检查。
- scan 必须返回起点及之后、按序、至多 limit 条的拥有结果，键和值都要相符。
- 序列结束时复核所有初始键和涉及的键，包括已删除或始终缺失的键。

校验通过后，每轮用全新实例加载同一批初始行，重放同一份操作。工厂创建和 bulk-load 计入构建耗时；独立参照、读回及最终状态检查在计时之外。计时阶段消费操作返回值以及扫描返回的键和值，避免编译器消除工作。

混合吞吐量的分母是完整序列的墙钟耗时，分子是操作数。一次 scan 无论返回多少行都只计一次操作，返回行数另行记录，因此不能把“ops/s”理解成“扫描行/s”，也不能从总耗时推算各操作类型的单独延迟。

所有实现复用同一份 `SIBROW1` 初始行和新 `SIBOPS1` 操作文件。操作文件只包含类型、键、新值和扫描上限，正确答案由 C++ 独立计算；报告保留哈希、数量和状态，不展开全部原始键。格式错误、适配器异常或错误返回都保留阶段与原因；失败组合不产生成功测量数据。

## 同学模型的预期覆盖

BlockLearn residual-delta 已声明 insert 与 scan，可先测读插混合和读插扫描；update/erase 仍不支持。Context16 适配包已声明 insert/update/erase/scan，可进入完整混合场景。具体支持仍以实际固定版本的 descriptor 和独立校验为准，不以仓库名推断。

本轮不覆盖并发写入、后台维护线程协议、混合负载下尾延迟、事务或持久化。静态并行评测见 [并行说明](PARALLEL_BENCHMARK.md)，模型接入见 [同学实现说明](TEAMMATE_INTEGRATION.md)。

固定版本上的实跑结果见 [混合主矩阵](experiments/mixed-operations-2026-10-17.csv) 和 [原生参数对照](experiments/model-parameters-2026-10-17.csv)；规模、通过范围与限制见 [本周记录](WEEKLY_UPDATE_2026-10-17.md#混合操作阶段的实际验证)。
