# 本周改进记录 · 2026-09-26

本周把“给出数据和实现的位置，就能得到评测报告”推进到了可运行的第一版。重点是接通评测流程，覆盖单线程静态点查询：先用完整键集合建好索引，再测试查找已有键和不存在的键。

## 相比上周，实际改善了什么

| 项目 | 上周 | 本周 |
| --- | --- | --- |
| 使用入口 | 统一命令还在设计文档中，实际测试走旧 TLI 工具 | 新增统一脚本，从数据路径和适配包路径开始运行 |
| 数据准备 | 需要按旧入口要求准备专用二进制格式 | 可读取原始行数据、JSONL 的指定字符串字段，也兼容旧二进制格式 |
| 换一个实现 | 旧入口需要在代码中注册索引 | 通过适配包描述文件发现并构建实现，同一次运行可比较多个适配包 |
| 查看结果 | 开发测试主要依赖日志和 CSV | 输出中文总览，并保留配置、原始样本和 CSV |
| 失败处理 | 容易需要到多处日志里查原因 | 每个请求的实现都有明确状态和失败阶段，未完成项不会伪装成性能结果 |

## 1. 用户把数据交进来，整理工作由评测层完成

新入口负责完整读取、排序、去重和统计。原始记录数、唯一键数和重复数都记录下来，原文件不被修改。空键、包含 NUL 的键、高位字节和长键能够进入统一的数据视图，不再沿用旧开发入口的 4096 字节过滤规则。

同时计算文件哈希和键集合的逻辑哈希：前者确认文件内容，后者确认实际比较的键集合。这样更换文件容器或调整行序后，仍能判断是否在评测同一组键。

## 2. 把“接一个索引”变成明确的适配工作

适配包说明源码位置、CMake 库目标和工厂函数，新入口自动构建对应的评测程序。首次接入第三方索引仍需要薄适配器，但以后换数据不必改它的源码。

附带 `std::map` 和排序数组二分查找两个基础适配包，便于验证接入流程、学习适配方式。它们是已有方法的基线，不属于新增学习型索引算法。

## 3. 先确认答对，再单独计时

多个实现共用相同数据和查询序列。入口先检查实现能力，再用独立参照核对答案；随后创建新实例，分别测量构建时间、吞吐量和延迟。

重复测量保留逐轮样本，能看出结果波动。校验开销不会混入性能结果，无法准确说明的内存分项标为不可用。实现不支持某类键时明确记录不兼容，不会偷偷删数据让它跑过去。

## 4. 结果能直接阅读，也能继续分析

每次运行生成四份文件：

- `report.md`：中文总览，先看是否测完、各实现状态和结果限制。
- `report.json`：完整参数、输入身份、实现能力和环境信息，便于复现。
- `summary.csv`：汇总指标，便于制作对比表格。
- `samples.csv`：原始轮次，便于检查波动和复算。

输入错误、实现不支持、跳过和运行失败分别记录；失败项不会以零吞吐量混入排名，也不会从报告中消失。

## 如何复现

在仓库根目录执行，输出目录必须尚不存在：

```bash
python3 -B scripts/benchmark.py \
  --dataset examples/keys.txt \
  --implementation adapters/std_map \
  --implementation adapters/sorted_vector \
  --output results/weekly-demo
```

先打开 `results/weekly-demo/report.md`。此命令只需 Python、CMake 和 C++17 编译器，无需下载真实数据或运行旧 setup。详细说明见 [统一入口使用指南](UNIFIED_BENCHMARK.md)。

## 实际怎么验过

- **自动测试通过**：新入口的 Python 测试 29 项全部通过；完整 CTest 6 个测试组全部通过，包含 C++ runner 和旧入口回归。旧 TLI smoke 的 60 个案例也全部通过。
- **文档命令跑通**：两个示例适配器都完成独立校验与测量，共用每轮 10,000 次查询，其中 1,000 次未命中，各重复 3 轮。
- **真正从仓库外接入**：将数据和适配包放到仓库外、带空格的目录，并从另一个目录调用脚本。9 条原始记录整理成 8 个唯一键，覆盖空键、NUL、高位字节、前缀键和 5,005 字节长键；两个实现均通过。
- **核对结果与保护行为**：仓库外实跑生成四份报告，保留 6 轮吞吐量和 6,000 个延迟样本；独立复算键集合哈希，核对构建身份，并确认源数据和适配源码未改变、重复指定已有输出目录会被拒绝。
- **检查失败路径**：加入坏输入、错误答案、不支持的能力、构建/运行失败、预算不足和报告结构异常等回归；独立代码审查发现的问题均已修正并复核通过。

## 本周没有把哪些事算成完成

第一版只覆盖静态点查询。插入、更新、删除、扫描、区间求和及混合负载、并发实验、更多真实索引适配，以及分片和外部 reader 接入，仍需要后续推进。数据准备目前使用内存排序去重。

本周验证用于证明接入、校验和报告链条能运行；小规模测试不能作为论文级的性能排名。旧 TLI 测试入口继续保留，历史结果按原有测量口径解释。
